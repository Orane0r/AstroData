# AGENTS.md

AstroData is a Nuxt 4 astronomy catalog: Nuxt UI frontend, Nitro API, NuxtHub SQLite + Drizzle. Use pnpm (`pnpm@11.1.3`); CI pins Node 22. `README.md` is the default Nuxt UI starter boilerplate — its `npm create nuxt` quick start and Vercel deploy button do not describe this repo.

## Commands

- `pnpm install` — also runs `nuxt prepare` via postinstall; rerun after pulling so `.nuxt` types are current.
- `pnpm dev` — http://localhost:3000. Migrations are applied on startup, and an empty or outdated DB is seeded.
- `pnpm lint` — `eslint .` with the flat config generated by `@nuxt/eslint`; auto-fix with `pnpm exec eslint . --fix`.
- `pnpm typecheck` — `nuxt typecheck` (vue-tsc). CI (`.github/workflows/ci.yml`) runs only `lint` then `typecheck`, on push. Tests are not run in CI.
- `pnpm exec vitest run` — one-shot Vitest (`pnpm test` is watch mode); `--project unit` or `--project nuxt` selects one project.
  - Single file: `pnpm exec vitest run --project unit test/unit/example.test.ts`.
  - Currently fails at config load with `DOMException [DataCloneError]` from `structuredClone` in `@nuxt/test-utils` (reproduced on Node 24). Verify behavior against a real dev server rather than trusting a green test run.
- `pnpm test:e2e` — Playwright, starts Nuxt itself (no separate dev server); single file: `pnpm exec playwright test tests/example.spec.ts`.
- `opencode.jsonc` holds this project's permissions: edits need approval, `git status *` / `git diff *` are allowed, `git commit *` and `git push *` are denied.

## Layout

- `app/` — Nuxt 4 srcDir: pages, components, composables, utils. Components and utils are auto-imported.
- `server/` — Nitro: `api/`, `db/` (Drizzle schema, seed, migrations), `services/` (NASA + Wikipedia HTTP), `mappers/`, `middleware/`, `tasks/`, `utils/`.
- `shared/` — used by both sides via `~~/shared/...`; `shared/utils/*` is auto-imported in both app and server.
- `i18n/locales/{en,fr}.json` — default locale is `fr`; add every new key to both files.

## Slug contract

- `celestial_bodies.slug` is the only public identifier; `id` is internal and changes on every re-seed. Routes, API params and links all use `[slug]`, and a legacy numeric URL must stay a 404 (no redirects).
- Slugs are built at seed time by `buildSlugMap` (`server/mappers/solar-system-to-db.ts`): slugified English name, dataset `id` as fallback, `-${type}` suffix only on collision (`metis-moon` vs `metis-asteroid`).
- `isSlug` (`shared/utils/string.ts`) is defined as `slugify(value) === value`; keep generation and validation in sync through it instead of adding a regex.

## Server/API quirks

- `server/middleware/validation.ts` matches `/api/celestial-bodies/<slug>` plus `/moons|description|images` with a hand-written regex, then validates the format (400) and existence (404). It stores nothing: each handler re-queries by slug, so two queries per request are expected — do not reintroduce `event.context` sharing. Add any new named or nested route to the regex and its exclusion list (`averages`, `count`, `types`) or it returns 400.
- `db` and `schema` are Nitro auto-imports (`@nuxthub/db`); `hub:db` and `hub:db:schema` also work. Existing routes mostly use `hub:db`.
- `images` and `description` use `defineCachedEventHandler`, so responses stay stale until the cache is invalidated; both call NASA/Wikipedia (no API key needed). Keep network out of tests.
- Keep the top-level `import '@libsql/client'` in `nuxt.config.ts`: it prevents a libsql native-addon crash in Nitro dev workers on Windows (upstream issue linked in the comment).

## Database

- Schema: `server/db/schema.ts`; commit migrations under `server/db/migrations/sqlite/`; local DB is `.data/db/sqlite.db` (gitignored).
- `pnpm exec nuxt-db generate` / `pnpm exec nuxt-db migrate` — the `npx nuxt db ...` header comment in `schema.ts` is stale. Review generated SQL: `0004_polite_punisher.sql` (the `slug` column) is hand-written to drop and recreate the table, because SQLite cannot add a `NOT NULL` column without default to a populated table.
- `server/db/seed.ts` deletes and re-inserts every body in one transaction, reading `solar_system.json` / `wikipedia.json` through static JSON imports. It re-seeds when the table is empty, after a new entry in `_hub_migrations`, or when `SEED_DATA_VERSION` is bumped (bump it when the JSON changes without a migration). The seed is destructive: never run it against data you need.
- Runtime status: `GET /api/system/database-status` runs `checkDatabaseSeed()`; `POST` retries a failed seed. Manual seed task in dev: `/_nitro/tasks/seed` (list at `/_nitro/tasks`).
- `server/data/messier.json` and `meteorite_landings.json` are not read by any code; do not assume they are loaded.

## UI conventions

- Nuxt UI v4 + Tailwind v4. A custom color needs both its name in `nuxt.config.ts` (`ui.theme.colors`) and its palette in `app/app.config.ts` (`ui.colors`); palettes not shipped by Tailwind (e.g. `brown`, used by `earth`) must be declared in `app/assets/css/main.css`.
- Icon sets: Solar (`i-solar-*`, dev-only `@iconify-json/solar`), Simple Icons, and Lucide.
- ESLint is the formatter (no Prettier): 2 spaces, single quotes, no semicolons, `commaDangle: 'never'`, `braceStyle: '1tbs'`.
- `app/utils/body-config.ts.ts` really has a doubled `.ts`; pages import it explicitly as `../../utils/body-config.ts` and use `useBodyTypeConfig`.

## Tests

- Vitest projects: `unit` (`test/unit/*.test.ts`, node) and `nuxt` (`test/nuxt/*.test.ts`, happy-dom); Playwright uses `tests/` (see `playwright.config.ts`), not `test/e2e/`. `test/nuxt/` is empty.
- Existing tests are scaffolds: `tests/example.spec.ts` expects a `/Nuxt/` title while the app title is `AstroData`. Coverage is always on (`vitest.config.ts`).
